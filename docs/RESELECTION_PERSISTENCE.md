# 设备身份拒绝状态持久化补丁

基线：f60a8aedf65ea731cc4ee319c07380402c68ece0，原历史与 evidence 均保留。

## 根因和最小变更

原先“需要重新选择”只存在于 QComboBox 的 RESELECTION_REQUIRED_ROLE，保存仅含 index/name。
同名设备明确选择后移除其中一个，当前窗口能够拒绝剩余同名设备；关闭重开丢失拒绝状态后，会把剩余同名设备当成唯一匹配恢复。

现在各设备存档仅在拒绝状态附加 requires_reselection: true。恢复、连续刷新、保存、关闭重开均保留此拒绝；用户明确选择真实设备或系统默认才清除。当前枚举快照、临时信任、硬件身份推断均不持久化。旧 index/name 存档兼容。

零设备枚举也保存拒绝状态，防止关闭后插入同名设备被信任。首次枚举直接抛异常、组合框尚未建立时不覆盖旧存档。重选后立即更新提示。

## 证据与回归

新增 5 项离线 GUI 回归（真实 Qt 控件，模拟设备枚举与流水线）：
- 同名设备选择→移除→要求重选→保存/关闭重开→反复刷新仍拒绝且不创建流水线→明确重选后创建并启动流水线。
- 明确选择系统默认解除持久化拒绝，重开仍为系统默认。
- 零设备后保存关闭，同名设备返回仍拒绝。
- 已有同名选择后枚举抛异常，也撤销临时信任并持久化拒绝；关闭后仅同名剩余设备仍拒绝。
- 输入与监听设备同样持久化拒绝，开启监听时阻止启动。

旧代码加新测试：14 项，3 个断言失败（before-reproduced.txt）。首次环境探测缺 PortAudio，补充官方 Debian 运行库和发现链接后完成实际复现，before.txt 保留该环境错误。中间全套出现 1 项旧存档保护回归，已修复且保留 gui.txt 原始结果。

独立复查另发现枚举异常后关重开的同名误恢复，review-before.txt 复现 1 个失败，已修正。最终结果为 review-final-*，早期阶段证据均保留。
